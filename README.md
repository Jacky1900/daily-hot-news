# 每日全球热点推送（金融 / AI科技 / 生物医药科技）

挂在 GitHub 上的定时脚本：每天自动从国外主流网站和论坛抓取过去 24 小时热度最高的新闻，
**分三类推送：金融股票 10 条、AI科技 10 条、生物医药科技 10 条**，
通过**微信（PushPlus）**和**邮件**推送给你。

**分工：微信用来扫标题，邮件用来读详情。**

- 定时：北京时间每天 **06:37 / 22:37**（特意避开整点，整点最容易被 GitHub 排队延迟）
- **微信收到 1 条消息**：三类全部 30 条标题，**自动翻译成中文**（用 Google 免费翻译，不用配置）
- **邮件收到 1 封详细报告**：英文标题 + **英文摘要**，想看中文直接用 **QQ 邮箱自带的「翻译邮件」**（网页版右上角 / App 里都有）
- 点标题直接跳原文
- **涉华报道一律过滤**（标题或摘要出现 China / 北京 / 台湾 / 华为 / 人民币等词，整条不推）
- **恒瑞医药例外**：只要提到 Hengrui / 恒瑞，一律保留并优先置顶
- 当天已推送过的条目自动去重，不会重复轰炸
- **可用邮件远程暂停/恢复**（邮件主题只写 `stop` / `start`，见下文）

数据源：Hacker News（有点赞数，真热度）、Reddit（有点赞数）、Google News、
MarketWatch、CNBC、TechCrunch、Ars Technica、MIT Tech Review、OpenAI、
Endpoints News、BioPharma Dive、STAT、Labiotech。
任一源挂掉自动跳过，不影响其他源。

## 第一步：准备 3 样东西（约 10 分钟）

### 1. PushPlus Token（微信推送用）

1. 微信搜公众号 **PushPlus** 并关注（或浏览器打开 `www.pushplus.plus` 扫码登录）
2. 登录后在网页上就能看到你自己的 **Token**（一串字母数字），复制下来
3. 免费版每天 200 条，本脚本一天只用 3 条，绰绰有余

### 2. 两个邮箱：小号负责发，主号负责收

**这套脚本用「小号发信 → 主号收信」的方式工作**，所以要准备两个邮箱：

| 角色 | 做什么 | 要开什么 | 要填的 Secret |
|---|---|---|---|
| **小号邮箱** | 脚本用它**发**邮件出去 | 开 **SMTP + IMAP**，拿授权码 | `SMTP_USER` / `SMTP_PASS` |
| **主号邮箱** | 你日常**收**邮件阅读 | **什么都不用开** | `MAIL_TO` |

**小号怎么拿授权码**（以 QQ 邮箱为例）：

1. 登录小号邮箱 `mail.qq.com` → 右上角 **设置** → **账户**
2. 往下拉找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**
3. 开启 **IMAP/SMTP 服务** 或 **POP3/SMTP 服务**，按提示发条短信验证
4. 页面会显示一串 **授权码**（16 位字母），复制下来（不是 QQ 密码！）

> 163 小号也行：`mail.163.com` → 设置 → POP3/SMTP服务 → 开启 → 拿授权码。
> 用 163 的话还要额外配 `IMAP_HOST = imap.163.com`。
> 主号是 163/Gmail 都无所谓，它只收信，不需要任何配置。

**为什么要分成两个？** 小号只用来发信、暴露了也不心疼；主号是你日常用的，不开放任何服务端口，更安全。

### 3. GitHub 仓库（第二步建，先注册登录好 github.com）

> **翻译不用配**：微信标题自动调 Google 免费翻译接口（无需 Key、无需注册）。
> 邮件保持英文，用 QQ 邮箱的「翻译邮件」看中文即可。
>
> 万一哪天 Google 接口失效（微信里标题变纯英文），可以再去配百度翻译做备份：
> `fanyi-api.baidu.com` 注册开通 → 拿 APP ID + 密钥 → 填进 Secrets 即可，脚本会优先用百度。
> **注意百度免费额度只有 5 万字符/月**（标准版），我们这套每天要翻 30 条标题、约 2.4 万字符/月，
> 需要做个人实名认证升到高级版（100 万/月免费）才够，否则会按 49 元/百万字符扣费。

## 第三步：配置 Secrets（仓库里存密码的地方）

仓库页面 → **Settings** → 左侧 **Secrets and variables** → **Actions** →
**New repository secret**，逐个添加下面 6 个：

| Name（名字，照抄） | 填什么 | 说明 |
|---|---|---|
| `PUSHPLUS_TOKEN` | 你的 PushPlus Token | 微信推送 |
| `SMTP_HOST` | `smtp.qq.com`（小号是 163 则填 `smtp.163.com`） | 小号的发信服务器 |
| `SMTP_PORT` | `465` | 固定填这个 |
| `SMTP_USER` | **小号邮箱**地址，如 `xiaohao001@qq.com` | 脚本用它发信 |
| `SMTP_PASS` | **小号邮箱**的授权码（16 位） | 不是登录密码 |
| `MAIL_TO` | **主号邮箱**地址，如 `wo@163.com` | 你收信的地方 |

**举个具体例子**（假设小号 QQ、主号 163）：

```
SMTP_HOST = smtp.qq.com
SMTP_PORT = 465
SMTP_USER = xiaohao001@qq.com      ← 小号（发）
SMTP_PASS = 小号的 16 位授权码
MAIL_TO   = wo@163.com              ← 主号（收）
```

> 主号**不需要开任何服务、不需要授权码**，它纯粹是收信地址。

下面 2 个**不用配**，除非以后 Google 翻译失效想换百度：

| Name | Value | 说明 |
|---|---|---|
| `BAIDU_TRANS_APPID` | 百度翻译 APP ID | 配了会**优先用百度**，不配就用 Google 免费接口 |
| `BAIDU_TRANS_SECRET` | 百度翻译密钥 | 同上 |

> 只加微信不加邮件也能跑（反之一样），脚本会跳过没配的渠道。

## 内容过滤说明（涉华报道一律不推）

**规则**：标题或摘要里出现下面任一关键词，整条直接丢弃，三类全部生效：

- **国家与地区**：China、Chinese、PRC、Beijing、Shanghai、Shenzhen、Hong Kong、Taiwan、TSMC、Xinjiang、Tibet、Uyghur
- **政治机构与人物**：CCP、Communist Party、Politburo、Xi Jinping、Tiananmen
- **中国企业**：Huawei、TikTok、ByteDance、Alibaba、Tencent、Baidu、DJI、SMIC、CATL、BYD、Xiaomi、Geely、NIO
- **货币**：Renminbi、Yuan

**恒瑞医药是唯一例外**：标题或摘要里出现 `Hengrui` 或 `恒瑞`，不管涉不涉华一律保留，
而且额外加 60 分，保证排在生物医药类的前面。数据源里专门加了一组
Google News 查询 `Hengrui OR "Jiangsu Hengrui" OR "恒瑞医药"`，专门捞恒瑞的新闻。

**代价**：台积电（TSMC）供应链、中国生物制药同行获批 FDA 这类新闻也会一起被过滤掉（恒瑞除外）。

**想放宽**（只过滤涉华政治、保留涉华科技产业新闻）：打开 `news_bot.py`，
把 `FILTER_ALL_CHINA = True` 改成 `False`。

**这个过滤器不可能 100% 准确**：靠的是关键词匹配，不是语义理解。个别用词隐晦的报道
可能漏网，个别含 "yuan" 之类词的无关新闻可能被误杀。日志里会打印
`过滤涉华报道 N 条 | 恒瑞医药白名单保留 M 条`，想知道拦了多少可以看那里。

## 公开仓库安全说明（重要，建议读一遍）

**公开仓库里，别人能看到什么：**
- 能看：全部代码（`news_bot.py`、workflow、README）
- 能看：**Actions 的运行记录和日志**（公开仓库的日志对所有人可见）
- 看不到：Secrets 的值（加密存储，只在运行时注入，事后连你自己都查不到）

**GitHub 自带的打码机制有边界**：它会把日志里出现的 secret 原值替换成 `***`，
但如果值被"变形"后输出（截断、拼接、编码），就可能认不出来。所以不能只靠它。

**这套脚本自己做了三层防护：**

1. **代码里零凭证**——所有敏感值都从环境变量读，源码里没有真实邮箱、没有 token
2. **日志统一脱敏**——所有输出都过一层 `redact()`，Token、授权码、邮箱（连"服务器只回显邮箱前半截"这种边角情况）全部替换成 `***`，实测输出：
   ```
   邮件推送失败: 535 auth failed, user=*** pass=***     ← 完整值被抹掉
   服务器回显: user *** not found                      ← 只回显前半截也被抹掉
   PushPlus 异常: token=*** invalid
   ```
3. **workflow 只监听「定时」和「手动触发」**——不监听 PR。陌生人 fork 你的仓库、在 workflow 里加一行 `echo ${{ secrets.XXX }}` 再提 PR，**触发不了你的工作流**，偷不到任何东西。

**你自己要守的三条红线：**

1. 永远不要把 Token / 授权码贴进代码、README、issue 里提交
2. 万一误提交了：立刻去服务后台作废重发（PushPlus 重置 Token、QQ 邮箱作废授权码），旧码就成了废码
3. 不确定就不提交——配 Secrets 才是唯一正确的位置

**如果你连"邮箱地址被人知道"都介意：**
注册一个专用小号邮箱（163 免费小号即可）只用来收这个推送，`SMTP_USER` 和 `MAIL_TO` 都填它。
万一哪天日志真出问题，暴露的也只是个一次性小号，跟你常用邮箱无关。

## 用邮件远程开关脚本（随时叫停）

**用主号发一封邮件到小号，主题只写一个单词。**

```
发件人：主号（MAIL_TO）
收件人：小号（SMTP_USER）
主题：
```

| 想干什么 | 邮件主题只写 |
|---|---|
| **暂停抓取** | `stop` |
| **恢复抓取** | `start` |

> ⚠️ 一定是从**主号发、发给小号**。脚本只登录小号的信箱读指令（它只有小号的授权码），
> 而且只认主号这个发件人——小号自己发的、陌生人发的，一律不认。

**为什么一个单词就够、又不会误停？**

脚本用的是**「主题完全相等」匹配**，不是"包含"匹配。实测对照：

| 邮件主题 | 会不会停脚本 |
|---|---|
| `stop` / `STOP` / `Stop`（大小写都行） | ✅ 会停 |
| `Re: stop` / `回复：stop`（自动加前缀也行） | ✅ 会停 |
| `Stop loss triggered`（券商止损通知） | ❌ 不会 |
| `Never stop learning`（订阅邮件） | ❌ 不会 |
| `stop now`（多了别的字） | ❌ 不会 |

所以哪怕你邮箱里天天收到带 stop 的英文邮件，也不会误停。

**跟你另一个脚本也不冲突**：那个用"停"字，这个用 `stop`，互不相干。

**工作机制（看完更放心）：**

脚本**只拿到小号的授权码**，主号一个字符都没给：

```
主号（你操作）  --发指令-->  小号（脚本登录读取）
                               ↑
                    脚本只有这个小号的授权码
```

- 脚本**每次运行前**（北京早 6:37 / 晚 22:37）会先用 IMAP 只读查一次**小号的收件箱**
- **只认主题，不认正文**——正文里写 stop 不会触发，防误判
- **指令只认主号发出**（`MAIL_TO`）——小号自己发的不认，陌生人发的也不认，
  口令 `stop` 虽然写在代码里是公开的，别人知道你小号也没用（日志会记一条"忽略非本人发来的指令"）
- **只读模式**：不标记已读、不移动、不删除任何邮件，查完就断开
- 暂停后，脚本每次运行会直接跳过（Actions 显示绿勾，不是报错）
- 暂停/恢复成功时，微信会收到一条确认消息（`⏸ 脚本已暂停` / `▶️ 脚本已恢复`）
- 只检查**最近 30 天**、最多**最近 40 封**邮件，按时间倒序找**最新的一条**指令为准

**和你另一个脚本（用"停"字）会不会打架？**

不会，但有一个操作细节要守住：**发 `stop` 邮件时，正文别写中文"停"字**。

| 你发的邮件 | 这个新闻脚本 | 另一个脚本（认"停"） |
|---|---|---|
| 主题 `stop`，**正文留空** | 暂停 ✅ | 不受影响 ✅ |
| 主题 `stop`，正文写"停止这个脚本" | 暂停 ✅ | **可能也被停** ⚠️ |
| 主题 `停` | 不受影响 ✅ | 暂停 ✅ |

原因是你的另一个脚本可能是扫正文找"停"字的，而它读不到你这个脚本的心眼——
所以最稳的发法就是：**主题只写 `stop`，正文一个字都别写**。

**注意事项：**

1. 邮箱必须开启 **IMAP 服务**（第一步开 SMTP 的同一个页面里，有个 IMAP/SMTP 一起开关的选项）
2. 用 163 邮箱的话，要额外加一个 Secret：`IMAP_HOST` = `imap.163.com`（QQ 邮箱不用配，默认就是 `imap.qq.com`）
3. 想换成别的口令：打开 `news_bot.py`，改 `STOP_SUBJECT` / `RESUME_SUBJECT` 两行（注意匹配是"完全相等"，改了就按新词精确匹配）

## 常见问题

**Q：到点没收到推送？**
- GitHub 定时任务在高峰时段可能延迟 5~15 分钟，属正常现象
- 去 Actions 页面看日志：绿色勾=成功，红叉=失败，点进去能看清哪一步出错
- 常见失败原因：Secrets 名字打错、授权码过期、PushPlus token 不对

**Q：微信没收到，但日志显示"推送成功"？**
- 确认微信关注了 PushPlus 公众号，且 Token 填的是自己的

**Q：GitHub 提示定时任务被禁用了？**
- GitHub 规定仓库 60 天无任何活动会自动停用定时任务。手动点一次 Run workflow 即可恢复

**Q：想改推送时间？**
- 编辑 `.github/workflows/news.yml`，改里面的 `cron` 行
- cron 是 UTC 时间，**北京时间 = UTC + 8 小时**。比如想改到北京时间 7:00，UTC 就是前一天 23:00，写 `0 23 * * *`

**Q：想改每类条数 / 加数据源 / 加分类？**
- 打开 `news_bot.py`，顶部配置区都有中文注释：`TOP_N`（每类条数）、`SOURCE_CAP`（单源上限）、
  `RSS_FEEDS`（RSS 源）、`HN_QUERIES`（HN 查询词）、`GOOGLE_NEWS_QUERIES`（Google News 查询词）、
  `REDDIT_SUBS`（Reddit 板块）。照着现有格式加一行就行

**Q：微信里的标题变成纯英文了？**
- 说明 Google 免费翻译接口暂时不可用（这类非官方接口偶尔会抽风）。推送本身是正常的，只是没中文
- 解决办法：去配百度翻译（见第一步末尾说明），填进 Secrets 后脚本会自动优先用百度
- 日志里搜 `Google 翻译` 能看到具体报错

**Q：同一条新闻一天内会重复推吗？**
- 不会。当天推过的条目记在 `state/pushed.json`，由 Actions 每天自动提交回仓库。第二天自动清零重新计
